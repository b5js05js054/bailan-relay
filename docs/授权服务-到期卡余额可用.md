# 授权服务：时长到期但有余额的卡继续可用

状态：方案，尚未上线  
日期：2026-11-12  
机器：`devin.08879.cn`（`186.241.81.160`）  
目录：`/www/wwwroot/devin.08879.cn/backend`

## 1. 现象

账号名下的时长卡已经到期时，直接用充值码（`TP-` 开头）：钱到账了，但开不了授权。客户端提示「充值成功，但自动开通授权失败：该卡密已过期」。

从没买过卡的新账号不受影响：充值接口会给它新建一张不限时长的余额卡，激活正常。

## 2. 原因

客户端在 11-05 已经按「到期但有余额仍然有效」改过（提交 `4dace60`），授权服务没有跟上：

- `user-redeem` 把钱充到客户端指定的卡，或者账号最近的一张卡，不管这张卡是否到期。
- `activate` 和 `heartbeat` 遇到到期的卡一律拒绝，不看余额。
- 给中继的吊销列表 `/api/license/revoked` 也把到期卡全部列进去。
- 签令牌时有效期按「卡到期时间」封顶，到期卡签出来的令牌本身就是过期的。

线上数据（2026-11-12）：到期卡里还有余额的有 13 张，合计 ¥171，属于 7 个账号，另有 1 张没绑定账号。这个问题 11-10 就出现过，和 11-11 晚上的重新部署无关。

## 3. 规则

**时长到期后，只要卡里余额大于 0，这张卡就继续可用；余额用完才算到期。**

这条规则带来的结果，需要业务上认可：

- 卡里一旦有余额，时长就不再起作用。免费模型在余额用完之前也能一直用。
- 时长卡只对余额为 0 的人有意义。
- 现在压在到期卡里的 ¥171 会自动恢复可用，不需要迁移数据。

## 4. 改动

只改两个文件，数据库不动，客户端不动，中继不动。

### `app/service.py`

新增一个函数，`effective_status` 保持原样（后台卡密列表仍按它显示「已过期」）：

```python
def usable_status(card: CardKey) -> str:
    """卡现在能不能用（不写库）。与 effective_status 只差一条：
    时长到期但余额大于 0 的卡仍算可用，余额用完才算到期。
    激活、心跳、余额/用量接口、给中继的吊销列表都按它判断。
    """
    status = effective_status(card)
    if status == STATUS_EXPIRED and int(card.balance or 0) > 0:
        return STATUS_ACTIVE
    return status
```

`activate()` 和 `heartbeat()` 里各有一句 `status = effective_status(card)`，都改成 `status = usable_status(card)`。

### `app/routers/license.py`

1. 导入改为 `from ..service import activate, heartbeat, log_action, usable_status`。
2. `_token_response`：到期卡的令牌不再按到期时间封顶。

```python
card_exp = as_utc(card.expires_at)
# 到期但靠余额继续可用的卡：令牌不再按到期时间封顶，否则签出来就已经过期。
token_cap = card_exp if card_exp is not None and card_exp > now_utc() else None
token, token_exp = create_license_token(card.code, card.device_id or device_id, token_cap, card.user_id)
```

   返回给客户端的 `card_expires_at` 仍是真实到期时间。

3. `_card_from_token`：`effective_status(card) != STATUS_ACTIVE` 改成 `usable_status(card) != STATUS_ACTIVE`。
4. `revoked_codes`：`st = effective_status(card)` 改成 `st = usable_status(card)`。

`user-redeem` 的逻辑不用改：钱充进到期卡后，这张卡按新规则就是可用的，客户端随后的自动激活会通过。

## 5. 改完之后的行为

| 情况 | 结果 |
|---|---|
| 时长没到期 | 和现在一样 |
| 时长到期，余额大于 0 | 激活、心跳都通过；令牌有效 30 分钟并正常续期；中继放行 |
| 时长到期，余额为 0 或为负 | 和现在一样被拒绝；1 分钟内进入中继吊销列表 |
| 到期且没余额时用充值码 | 钱充进这张卡，客户端自动激活通过，可以直接用 |
| 卡被禁用 | 和现在一样被拒绝 |
| 卡绑定在别的电脑上 | 和现在一样被拒绝（一卡一机不变） |

不在这次改动里：

- 同一账号多张到期卡里的余额不会合并，每张卡各用各的。
- 后台卡密列表里，这类卡仍显示「已过期」。

## 6. 上线步骤

1. 备份 `app/service.py` 和 `app/routers/license.py`。
2. 先在一份代码副本上用空的测试库跑一遍上表的每种情况，不碰线上数据。
3. 改线上文件，`py_compile` 通过后重启授权服务。
4. **重启时注意中继**：中继进程是授权服务拉起来的子进程，和它在同一个会话里。授权服务一停，中继会跟着停，而且服务启动时不会自动拉起中继。重启后要立刻把中继启动起来，并确认端口在监听。应挑没有对话进行的时候做。
5. 登录状态不受影响：登录密钥已经存在 `data/admin_jwt_secret.key` 里，重启不会再让客户掉登录。

## 7. 怎么核对

- 请求 `/api/license/revoked`：有余额的到期卡不再出现在列表里。
- 用一个「卡已到期、有余额」的账号登录客户端：授权显示有效，收费模型能发消息并正常扣费。
- 用一个「卡已到期、余额为 0」的账号在激活框里输入充值码：提示充值成功，授权变为有效。
