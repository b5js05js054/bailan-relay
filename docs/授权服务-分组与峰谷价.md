## 1. 分组名和分组倍率

### 现象

模型页的「分组」只剩「全部」和「未分类」，「倍率」只剩「全部」。厂商芯片还在，因为厂商是客户端按模型名字判断的。

### 原因

库里的数据还在：

- `client_model.category` 存的是分类 ID，例如 `cat-p2poolyivsvy`
- `app_setting.key = model_categories` 里有 `id`、`name`、`multiplier`

`enabled_client_models` 组包时没有把名字和倍率放进返回值。客户端只认 `category_name`、`category_multiplier`，对不上就全部显示「未分类」。

### 改动

文件：`app/client_models.py`

- 增加 `import json`
- `from .models import AppSetting, AppUser, ClientModel`
- 新增 `_category_names(db)`：读 `model_categories`，得到 `{分类ID: 显示名}`
- `enabled_client_models` 里每个模型增加：

```python
"category_name": names.get(row.category or "", ""),
"category_multiplier": billing.category_multiplier(row, settings),
```

`category_multiplier` 沿用 `billing.category_multiplier`：没填分类、或分类表里没有这个 ID，按 `1.0`。

改前备份：`app/client_models.py.bak-category-20261109144537`

## 2. DeepSeek 高峰 / 空闲价

### 现象

DeepSeek 卡片只有一个现价，没有高峰、空闲两行。

### 原因

客户端 `scheduleQuote` 只在模型带 `price_tiers.peak` 和 `price_tiers.off` 时画这两行。

后台原来只下发：

- `price_in` / `price_out` / `price_cache` / `price_cache_write`：此刻生效的现价（已含分组倍率，命中时段时已经换成时段价）
- `price_schedule`：原始时段，单价是每百万 token 的基础价，还没乘分组倍率
- `schedule_active`：现在是否落在时段里

没有 `price_tiers`。客户端不会自己把 `price_schedule` 拆成两档。

DeepSeek 的时段存在 `client_model.price_schedule`。以 `deepseek-v4-flash` 为例：工作日，`Asia/Shanghai`，09:00–12:00 和 14:00–18:00，`price_input` 都是 `2.0`。不在时段内用模型默认 `ratio`。

### 改动

文件：`app/billing.py`

- `from datetime import datetime, timedelta`
- `model_pricing(row, settings, now=None)`：把 `now` 传给 `apply_schedule`，才能按指定时刻算价
- 新增 `client_price_tiers(row, settings)`
- 新增 `_moment_in_slot(schedule, slot)`：找一个落在该时段、且符合生效日的时刻

规则：

- 没有启用中的时段：返回 `None`，JSON 里就是 `null`，卡片不画两行
- **空闲**：把 `price_schedule` 清空后再走 `model_pricing`，也就是模型默认定价
- **高峰**：所有时段里 `price_input` 最高的那一档。当前 DeepSeek 两个时段价格相同，所以就是时段价
- `active`：现在落在任一时段内为 `"peak"`，否则 `"off"`
- 价格口径与 `price_in` 相同：每百万 token 的现价，已乘分类倍率和全局倍率，不含单张卡密的分组倍率

文件：`app/client_models.py`

在上面两个字段旁边再加：

```python
"price_tiers": billing.client_price_tiers(row, settings),
```

返回形状：

```json
{
  "active": "off",
  "peak": {
    "price_in": 0.24,
    "price_out": 0.96,
    "price_cache": 0.0048,
    "price_cache_write": 0.0
  },
  "off": {
    "price_in": 0.12,
    "price_out": 0.48,
    "price_cache": 0.0024,
    "price_cache_write": 0.0
  }
}
```

上面是 `deepseek-v4-flash` 在分类倍率 0.12、全局倍率 1、`quota_per_unit` 500000 时的结果。带时段价的模型一共 12 个，都是 DeepSeek。

`billing.py` 没有单独备份。回退时删掉 `client_price_tiers`、`_moment_in_slot`，并把 `model_pricing` 的 `now` 参数和 `apply_schedule(row, settings, now)` 改回原来的 `apply_schedule(row, settings)`。

## 4. 怎么核对

登录后请求 `GET /api/license/client-config`，看任意 DeepSeek：

- `category_name` 不是空字符串
- `category_multiplier` 是该分类的倍率
- `price_tiers.peak` 和 `price_tiers.off` 都在，且高峰输入价高于空闲输入价

没有时段的模型，`price_tiers` 为 `null`。
