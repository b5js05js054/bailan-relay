# 号池状态：授权服务开发说明

客户端要展示号池账号的状态和用量。中转站地址和访问令牌只能留在授权服务上，不能进客户端安装包、配置或任何返回给客户端的内容。

授权服务代码在服务器 `186.241.81.160`：

```text
/www/wwwroot/devin.08879.cn/backend
```

进程是 screen 会话 `chatgpt_2` 里的 uvicorn，监听 `0.0.0.0:8000`。路由前缀 `/api/license`，实现在 `app/routers/license.py`。配置类是 `app/config.py` 的 `Settings`，从同目录 `.env` 读取。HTTP 客户端用已经安装的 `requests`，没有 httpx。

客户端只会请求已经公开的授权服务。新增接口和现有用量接口同一路：

```text
GET /api/license/pool-status
Authorization: Bearer <客户端授权令牌>
```

## 不要做的事

- 不要把中转站地址或访问令牌写进源码、提交进仓库、放进 `client-config`。
- 不要在 HTTP 响应、`HTTPException.detail`、返回给客户端的日志里出现中转站域名、令牌或上游原文。FastAPI 会把 `detail` 直接返回给客户端。
- 不要让客户端自己请求中转站。客户端里加密这个地址也没用，抓包和反编译都能看到。
- 不要用有钱包或 API 密钥的站点账号发令牌。单独建一个只能看号池的账号，令牌由管理员私下交给运维，写入服务器 `.env`。

## 配置

在 `app/config.py` 的 `Settings` 里增加：

```python
pool_base_url: str = ""
pool_access_token: str = ""
```

在服务器 `.env` 增加（值不要写进这份文档）：

```text
POOL_BASE_URL=https://中转站域名
POOL_ACCESS_TOKEN=专用账号的访问令牌
```

`pydantic-settings` 会把这两个字段读成上面的环境变量。改 `.env` 后要重启进程才生效。

## 接口

加在 `app/routers/license.py`，放在现有 `GET /usage` 旁边。鉴权复用 `_card_from_token`：必须是已激活卡密的授权令牌。未登录、令牌过期、卡密失效时保持现有 401 / 403，不要为了号池改这套错误文案。

成功时 HTTP 200：

```json
{
  "ok": true,
  "stale": false,
  "fetched_at": "2026-11-08T19:27:05+08:00",
  "total": 191,
  "groups": [{ "id": 23, "name": "ccmax2" }],
  "items": [
    {
      "id": "wcdkp2m2vqel",
      "name": "ma***72",
      "status": "active",
      "groups": [{ "id": 23, "name": "ccmax2" }],
      "usage_windows": [
        { "kind": "five_hour", "utilization": 3, "resets_at": "2026-11-08T23:00:00+08:00" },
        { "kind": "seven_day", "utilization": 99, "resets_at": "2026-11-11T19:00:00+08:00" },
        { "kind": "seven_day_fable", "utilization": 55, "resets_at": "2026-11-11T19:00:00+08:00" }
      ],
      "observed_at": "2026-11-08T19:23:00+08:00"
    }
  ]
}
```

字段含义：

| 字段 | 说明 |
|---|---|
| `items[].id` | 账号主键，长期稳定。客户端用它区分账号 |
| `items[].name` | 已打码的显示名，不保证唯一 |
| `items[].status` | `active` 可用，`paused` 暂时不可用，`unavailable` 停用或异常 |
| `items[].groups` | 所属分组，可能是空数组 |
| `items[].usage_windows` | 用量窗口，可能是空数组。顺序不固定，客户端会自己排序 |
| `items[].usage_windows[].kind` | 已知值：`five_hour`、`seven_day`、`seven_day_sonnet`、`seven_day_fable`。以后可能新增，原样透传 |
| `items[].usage_windows[].utilization` | 已用百分比，通常 0–100 |
| `items[].usage_windows[].resets_at` | 下次重置时间。`null` 表示没有重置时间，或窗口已经重置 |
| `items[].observed_at` | 这个账号用量的记录时间，可能早于 `fetched_at` |
| `groups` | 全部分组，不受筛选影响 |
| `stale` | `true` 表示这次返回的是上一份成功数据 |
| `fetched_at` | 上游数据的更新时间，不是本接口的请求时间。没有数据时为 `null` |
| `total` | 账号总数 |

失败但进程还能回答时，也用 HTTP 200，方便客户端和用量接口一样看 `ok`：

```json
{ "ok": false, "message": "号池暂时不可用" }
```

只使用这一句中文。不要附上游状态码、域名或响应体。

## 向上游拉取

配置完整时，服务端请求：

```text
GET {POOL_BASE_URL}/api/pool/accounts?page_size=1000
Authorization: Bearer {POOL_ACCESS_TOKEN}
```

超时 30 秒。当前账号大约 200 个，一页 1000 条足够，不需要翻页。

上游成功时 HTTP 200，外层是：

```json
{ "success": true, "message": "", "data": { "items": [], "groups": [], "stale": false, "fetched_at": null, "total": 0 } }
```

把 `data` 里的 `items`、`groups`、`stale`、`fetched_at`、`total` 放进上面的成功响应。`message` 不要回给客户端，它会随上游语言变化。

上游行为：

- 没有号池数据时 `items` 为空、`total` 为 0，这是成功，不是故障。
- `success: false` 且 HTTP 200：功能未开、无权限、参数错误，或上游没有缓存。对客户端统一返回「号池暂时不可用」。
- HTTP 401：令牌无效或账号被停用。同上，不要把 `AUTH_UNAUTHORIZED` 这类码回给客户端。服务端日志可以记「号池令牌失效」，不要记令牌本身。
- HTTP 429：响应体为空，响应头有 `Retry-After`（秒）。有缓存就返回缓存并把 `stale` 设为 `true`；没有缓存就返回「号池暂时不可用」。不要立刻重试。
- 网络错误、超时、非 JSON：同样优先返回缓存。

所有客户端共用一份缓存，缓存 60 秒。上游自己也有大约 30 秒缓存，更频繁地请求不会更新。缓存放进程内存即可，加锁，不用入库。

建议单独放 `app/pool_status.py`，路由里只做鉴权和调用。伪代码：

```python
_lock = threading.Lock()
_cache = {"at": 0.0, "body": None}  # body 是已经整理好的成功响应


def pool_status() -> dict:
    now = time.monotonic()
    with _lock:
        cached = _cache["body"]
        fresh = cached is not None and now - _cache["at"] < 60
    if fresh:
        return cached

    settings = get_app_settings()
    base = settings.pool_base_url.strip().rstrip("/")
    token = settings.pool_access_token.strip()
    if not base or not token:
        logger.warning("号池状态未配置")
        return _fallback(cached)

    try:
        resp = requests.get(
            base + "/api/pool/accounts",
            params={"page_size": 1000},
            headers={"Authorization": "Bearer " + token},
            timeout=30,
        )
    except requests.RequestException:
        logger.warning("号池状态请求失败")
        return _fallback(cached)

    if resp.status_code != 200:
        logger.warning("号池状态上游状态码 %s", resp.status_code)
        return _fallback(cached)

    try:
        payload = resp.json()
    except ValueError:
        logger.warning("号池状态响应不是 JSON")
        return _fallback(cached)

    data = payload.get("data") if isinstance(payload, dict) else None
    if not payload.get("success") or not isinstance(data, dict):
        logger.warning("号池状态上游拒绝")
        return _fallback(cached)

    body = {
        "ok": True,
        "stale": bool(data.get("stale")),
        "fetched_at": data.get("fetched_at"),
        "total": data.get("total") or 0,
        "groups": data.get("groups") or [],
        "items": data.get("items") or [],
    }
    with _lock:
        _cache["at"] = time.monotonic()
        _cache["body"] = body
    return body


def _fallback(cached: dict | None) -> dict:
    if cached is None:
        return {"ok": False, "message": "号池暂时不可用"}
    stale = dict(cached)
    stale["stale"] = True
    return stale
```

路由：

```python
@router.get("/pool-status")
def pool_status_endpoint(authorization: str = Header(default=""), db: Session = Depends(get_db)):
    _card_from_token(db, authorization)
    return pool_status()
```

日志里不要打印 `POOL_BASE_URL`、`POOL_ACCESS_TOKEN` 或完整请求 URL。

## 验收

用一张已激活卡密的授权令牌请求：

```bash
curl -sS "http://127.0.0.1:8000/api/license/pool-status" \
  -H "Authorization: Bearer <卡密授权令牌>"
```

通过标准：

- HTTP 200，`ok` 为 `true`，`total` 大于 0，`items` 里有 `id`、`name`、`status`、`usage_windows`。
- 60 秒内连续请求，上游只会实际打到一次。
- 不带令牌时是 401，响应里没有中转站域名。
- 把 `POOL_ACCESS_TOKEN` 改错后重启：有旧缓存时 `ok` 仍为 `true` 且 `stale` 为 `true`；清掉缓存后再请求，得到 `{"ok": false, "message": "号池暂时不可用"}`。
- 在仓库和接口响应里搜索中转站域名，客户端可见的位置都没有。`.env` 和进程环境里有，这是预期。
